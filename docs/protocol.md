# m12d 串口协议（StackChan 对接用）

适用版本：m12d 0.1.0（`master`，2026-11-10）。M12 只负责报告检测和识别结果；什么时候问、拿结果做什么，由 StackChan 决定。

## 1 连接

- 接口：M12 的 Grove 口，接 StackChan 的 **UART** 口，TX 和 RX 交叉连接。
- 电平：3.3 V TTL。
- 参数：**115200 8N1**，无流控。
- 上电以后：M12 大约 **20–25 s** 开始输出（开机自启）。第一行输出可能是半行或者乱码，接收方应丢弃无法解析的行。
- 网络调试口：M12 插着 USB-C 时，还会在 `10.254.239.1:5555`（TCP）上提供**完全相同**的协议，可以在 Mac 上旁听。

## 2 消息格式

- 每条消息是**一行 JSON**，以 `\n` 结尾（`\r\n` 也接受）。M12 发出的每一行都是完整的一行。
- StackChan 发给 M12 的请求每行**最多 512 字节**。超长的行整行丢弃，M12 回复 `toolong`。
- 消息分三种，用字段区分：

| 种类 | 方向 | 怎么认 |
|---|---|---|
| 推送 | M12 → StackChan | 没有 `id`：要么有 `"f"`（检测行），要么有 `"hb"`（心跳） |
| 请求 | StackChan → M12 | `{"id":<整数>,"do":"<命令>", ...参数}` |
| 回复 | M12 → StackChan | 带同一个 `id`，外加 `"ok":true` 或 `"ok":false,"err":"<错误码>"` |

- `id`：0 到 2147483647 的整数，由 StackChan 自己编号。M12 原样带回，用来对上请求和回复。
- 回复只发回请求来自的那个通道（串口或某个 TCP 连接）。推送发给所有订阅了的通道，串口默认订阅。
- 回复和推送会交错到达，要按 `id` 对应，不要假设回复一定紧跟在请求后面。
- 收到不认识的字段请忽略。以后的版本只会追加字段，不会改动已有字段的含义。

## 3 推送

### 3.1 检测行（每次检测循环一条，有脸时约 15 行/秒）

```json
{"f":8542,"num":1,
 "face":[{"x":278.3,"y":143.9,"w":100.9,"h":140.6,"prob":0.972,
          "mark":[{"x":296,"y":184},{"x":316,"y":186},{"x":286,"y":208},{"x":296,"y":242},{"x":312,"y":242}],
          "id":1,"gender":"m","age":38,"age_group":"adult","name":"me"}],
 "running":"Face Detector",
 "person":[{"x":87.5,"y":121.6,"w":525.8,"h":389.4,"prob":0.991,"id":18,"face":1}]}
```

坐标都以 **640×480** 为基准，原点在左上角。

| 字段 | 含义 |
|---|---|
| `f` | 帧号，单调递增 |
| `num` | `face` 里有几张脸。画面里没人时为 0，这一行照样发 |
| `face[].x/y/w/h` | 脸框，1 位小数 |
| `face[].prob` | 检测置信度，≥ 0.8 才会出现 |
| `face[].mark` | 五点，整数，按画面左右排列：画面左侧的眼、画面右侧的眼、鼻尖、画面左侧的嘴角、画面右侧的嘴角。`cfg lm:false` 时不发 |
| `face[].id` | 跟踪编号：同一个人在连续帧里保持不变，离开画面超过 1 s 后会换新编号 |
| `face[].gender` | `"m"`、`"f"` 或 `"?"`（不确定）。新面孔出现约 0.6 s 后才有 |
| `face[].age`、`age_group` | 估计年龄和年龄段：`child` ≤12、`young` 13–29、`adult` 30–54、`elder` ≥55。和 `gender` 同时出现 |
| `face[].name` | 这张脸被 `who` 或 `learn` 认出来以后才有，见 §4.3 |
| `running` | 固定为 `"Face Detector"`，为了和原厂字段兼容 |
| `person[]` | 人形（全身或半身），用于 1.5 m 以外看不清脸的情况。最多 5 个，按 prob 从高到低。`cfg person:false` 时没有这个键 |
| `person[].id` | 人形的跟踪编号，和脸的 `id` 是两套独立的编号 |
| `person[].face` | 和这个人形配对的脸的 `id`（脸落在人形框的上部），没有配对时为 `-1` |

- `face` 按 prob 从高到低排列，最多 `max_faces` 张，默认 10。
- 新出现的人形要先过一次复核，才会出现在 `person` 里，所以会比实际出现晚 0.2–0.3 s。
- 没有脸时，人脸检测和人形检测轮流进行，这时可能有几行 `num:0`。

### 3.2 心跳（每 2 s 一条）

```json
{"hb":{"t":77,"fps":15.4,"tier":0,"up":2107,"mem":71284,"frames":894,"reopens":0,"drop":0,"mhz":1400}}
```

| 字段 | 含义 |
|---|---|
| `t` | 芯片温度，°C |
| `fps` | 检测帧率，按最近 2 s 计算 |
| `tier` | 0 表示正常；3 表示过热暂停：温度 ≥ 90°C 时停止检测，降到 87°C 以下自动恢复 |
| `up` | 系统运行时长，秒 |
| `mem` | 可用内存，KB |
| `frames` | 启动以来检测过的帧数 |
| `reopens` | 摄像头重新打开的次数 |
| `drop` | 因为通道太慢而丢弃的推送行数 |
| `mhz` | CPU 频率 |

- 过热暂停期间不发检测行，心跳照常。原厂的 95°C 保护也还在（触发后需要重新上电）。
- 现在只报告温度，不会因为温度自动降帧。降帧策略由 StackChan 根据 `t` 自己决定：例如用 `cfg fps_cap` 限帧，或者用 `cfg det:false` 进入待机。

## 4 请求与回复

### 4.1 基本命令

| 请求 | 成功时的回复 |
|---|---|
| `{"id":1,"do":"ping"}` | `{"id":1,"ok":true}` |
| `{"id":2,"do":"ver"}` | `{"id":2,"ok":true,"ver":"0.1.0","git":"…","models":["mnet.25-opt","genderage","yolo-fastest","mobilefacenet"]}` |
| `{"id":3,"do":"status"}` | `{"id":3,"ok":true,"hb":{…与心跳相同…}}` |
| `{"id":4,"do":"cfg", …可选参数}` | `{"id":4,"ok":true,"cfg":{"det":true,"lm":true,"attr":true,"person":true,"id_th":0.50,"max_faces":10,"fps_cap":0.0,"sub":true}}` |

**`cfg` 的参数**：都可以不带。不带参数时只读取当前配置；带了参数就修改。回复里总是给出修改后的完整配置。

| 参数 | 取值 | 作用 |
|---|---|---|
| `det` | bool | 检测开关。`false` 是待机：不发检测行，心跳照常，温度会下降 |
| `lm` | bool | 检测行里是否带五点 `mark` |
| `attr` | bool | 是否估计性别和年龄 |
| `person` | bool | 是否做人形检测，检测行里是否有 `person` |
| `id_th` | 0.3–0.9 | 人脸识别的阈值，见 §4.3 |
| `max_faces` | 1–10 | 检测行里最多带几张脸 |
| `fps_cap` | 0 或 0.5–30 | 检测帧率上限，0 表示不限 |
| `sub` | bool | 这个通道是否接收推送 |

- 有任何一个参数不合法时，整条请求都不生效，回复 `badarg`。
- 设置只在运行期间有效。重新上电后恢复默认值，也就是上表回复示例里的那组值。

### 4.2 人脸识别命令（按需执行，延迟回复）

这四条命令不会立即回复：请求先排队，在两帧之间处理完再回复，其间检测行照常推送。最多 4 个请求同时在处理，超出时回复 `busy`。每个请求最多 3 s，超时回复 `timeout`。

**选哪张脸**：`learn` 和 `who` 可以带 `"face":<脸的 id>`，id 来自检测行。不带时用画面里**最大**的那张脸。

| 请求 | 成功时的回复 | 说明 |
|---|---|---|
| `{"id":5,"do":"learn","name":"小明"}` | `{"id":5,"ok":true,"name":"小明","samples":5,"f":1234}` | 在约 0.6–1 s 内从同一张脸上采 5 个样本，存进人脸库。`samples` 是这个名字现有的样本总数 |
| `{"id":6,"do":"who"}` | `{"id":6,"ok":true,"f":1240,"face":1,"name":"小明","sim":0.768}` | 认不出时 `"name":null`，`sim` 仍然给出。库为空时 `sim` 为 0 |
| `{"id":7,"do":"forget","name":"小明"}` | `{"id":7,"ok":true,"name":"小明"}` | 删除这个名字和它的全部样本 |
| `{"id":8,"do":"faces"}` | `{"id":8,"ok":true,"faces":[{"name":"小明","samples":5}]}` | 列出库里的名字 |

- 名字：UTF-8，1–32 字节，不能含控制字符。
- 同一个名字可以多次 `learn`，样本会累加，每个名字最多 20 个，超出时丢掉最旧的。建议在不同角度和光线下各学一次。
- 人脸库最多 16 个名字。
- 人脸库保存在 M12 上，断电不会丢失。

**耗时**：`who` 通常约 0.27 s，偶尔到 0.45 s。`learn` 大约 1 s。每次识别会让检测停顿约 0.22 s，相当于少一帧多，所以不要高频轮询 `who`。

### 4.3 识别结果挂在检测行上

- `who` 认出某张脸，或者对它 `learn` 成功之后，检测行里这张脸会一直带着 `"name"`，**不需要反复 `who`**。
- 推荐用法：检测行里出现一个新的脸 `id`，并且它没有 `name` 时，发一次 `{"do":"who","face":<id>}`。
- 遇到下面几种情况，`name` 会被去掉。宁可去掉，也不让名字挂错人：
  - 这张脸离开画面超过 1 s；
  - 它和另一张脸的框重叠，比如两个人交错走过，这时跟踪编号可能互换；
  - 之后对它的 `who` 结果变了：变成别的名字就替换成新名字，变成 `null` 就清除；
  - 这个名字被 `forget` 删除了。

**阈值**：`sim` ≥ `id_th`（默认 0.5，与原厂相同）就算认出。
- 用户本人在正脸和常见角度下一般在 0.6–0.9；侧脸约 45° 或者 2 m 以外会降到 0.5 左右。
- **默认阈值还没有用其他人的脸验证过**，不保证不会认错人。验证之后可能调整默认值；运行时也可以用 `cfg id_th` 改。

## 5 错误码

回复格式为 `{"id":<id>,"ok":false,"err":"<码>"}`。

| 码 | 含义 |
|---|---|
| `badjson` | 不是合法的 JSON（这时 `id` 为 -1） |
| `toolong` | 行超过 512 字节（这时 `id` 为 -1） |
| `badarg` | 缺少 `id` 或者 `id` 不合法（这时 `id` 为 -1）；参数不合法；有多余的键；`forget` 的名字不存在 |
| `unknown` | 未知命令 |
| `busy` | 已经有 4 个识别请求在处理 |
| `timeout` | 3 s 内没有完成 |
| `noface` | 画面里没有可用的脸；指定的 `face` id 不在画面里；`learn` 采样途中人离开了或者换了人 |
| `standby` | 检测处于待机（`det:false`），这时 `learn` / `who` 不执行 |
| `hot` | 过热暂停中，这时 `learn` / `who` 不执行 |
| `nomodel` | 识别模型没有加载 |
| `full` | 人脸库已经有 16 个名字 |
| `conflict` | 新学的脸和库里另一个名字太像，没有存。回复里另外带上 `"name":"<那个名字>"` |
| `io` | 人脸库写入失败，这次修改已撤销 |

- `forget` 和 `faces` 在待机、过热时也照常执行。

## 6 调试命令

- `{"id":9,"do":"snap"}`：把最新一帧和它的检测结果存成 M12 上的文件 `/tmp/m12d_snap.yuyv`，只在开发时用。
