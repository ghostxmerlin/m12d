# m12d 阶段 0–1 实施计划：编译环境 + 复刻原厂人脸检测

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** 搭建可重复的 M12 交叉编译环境，并交付第一版常驻程序 m12d。
- 每帧做人脸检测，输出与原厂兼容的 JSON。
- 提供串口和 TCP 共用的统一指令集（设计 §6）。
- 在固定图片集上和原厂参照代码逐帧对比，结果一致。
- 在同等条件下帧率不低于原厂，CPU 和温度低于原厂；5 分钟对比运行不崩溃。
- 验收按设计 §10 的 A/B/C/D 四层进行。

**Architecture：**
- 全静态链接的 armhf 可执行文件，不依赖设备上的 OpenCV、libstdc++ 和 libgomp。
- 用 V4L2 mmap 采集 YUYV 640×480，自己完成"缩小一半并转 RGB"，再交给 ncnn RetinaFace 推理。
- 线程之间只用加锁的单槽缓冲和有界行队列通信，不允许空转等待。
- 一个 IO 线程用 poll 同时处理串口和 TCP。两者共用同一个行切分器和分发器，只是 fd 不同。
- 原厂参照程序只在主机上编译，链接主机 OpenCV，用于 B 层对比。设备产物不用 OpenCV。
- 后处理（anchor 生成、proposal、NMS）从原厂 `face_detector.cpp` 移植，线程和通信部分全部重写。

**Tech Stack：**
- C++17、CMake 3.16+、Ninja
- ARM gcc-arm-10.2-2020.11（aarch64 主机，目标 arm-none-linux-gnueabihf）
- ncnn 6afc736（静态链接，OpenMP + NEON）
- doctest 2.4.11
- Docker arm64 版 Ubuntu 20.04
- 设备端为 zsh 和 busybox

**Spec：** `docs/superpowers/specs/2026-11-09-m12-vision-design.md`（下文简称"设计"）。执行者必须同时阅读设计的 §3、§4、§9、§10。

**范围：** 只覆盖设计 §10 的阶段 0 和阶段 1（修订于 2026-11-09 晚：加入 B 层参照对比和统一指令集，D 层测试改为每组 5 分钟）。阶段 2–5（识别、属性、场景、投入使用）在拿到本阶段的实测数据后，另写计划。

## Global Constraints

- 所有推理都在 M12 上运行。Mac 和容器只负责编译和主机单元测试；主机上运行 ncnn 只用于对照测试。
- 产物必须**全静态链接**：`file` 输出含 `statically linked`，`readelf -d` 没有 NEEDED 条目。这样可以绕开设备上 glibc 2.30 和 libstdc++ 6.0.28 的版本限制。
- 编译目标：`-march=armv7-a -mfpu=neon-vfpv4 -mfloat-abi=hard`。
- ncnn 固定在提交 `6afc736225de2f1b193292e31ca6242d138463d4`，配置为 `NCNN_VULKAN=OFF`、`NCNN_OPENMP=ON`、`NCNN_SHARED_LIB=OFF`，不编译 tools、examples、benchmark。

- **设备端规则**：
  - 应用目录：`/home/m5stack/m12d/{bin,models,log}`。
  - 程序必须在 `/home/m5stack/m12d` 目录下以 `./bin/m12d` 的形式运行，这样原厂温控在 95°C 时也能杀掉它。
  - 访问摄像头和 ttyS1 需要 root，用 sudo。
- **严禁**：
  - 使用 `killall python3`、`S85runpayload stop`、`S110thermal stop`。
  - 在运行时关闭 Wi-Fi。
  - 修改 `/home/m5stack/payload`。
  - 把密码写入仓库。设备密码只从环境变量 `M12_PASS` 读取。
- 设备的 shell 是 zsh；用户 m5stack 不能写 `/dev/null`；没有 `pkill`；scp 和 sftp 不可用。传文件一律走 `ssh ... 'cat > file'`。
- 每次在设备上跑负载测试，温度达到 90°C 时都必须自动中止。
- 默认参数：
  - 检测阈值 prob 0.8，NMS 0.4，检测输入 320×240。
  - 采集 320×240、10fps，检测直接用 1:1 转换。可以用 `--cap-size 640x480` 改回 2×2 平均缩小的方式。这是 2026-11-09 实测后用户决定的，见 `results/2026-11-09-capture-experiments.md`。

  - 串口 `/dev/ttyS1`，115200 8N1。

  - 请求行最长 512 字节。

## Review Focus

1. **摄像头读帧失败或超时**（USB 摄像头复位、select 超时）：采集线程关闭并重新打开设备，带 500ms 退避；在心跳里累计 `reopen`；检测线程不崩溃，只是没有新帧。在 Task 5 中用 FakeCamera 测试。
2. **串口或 TCP 对端不读，或发送缓冲区满了**：不能阻塞检测，也不能拖住其他通道。
   - 每个通道各有一个有上限的发送缓冲。满了就丢弃整行（绝不发半行），并计数。
   - 推送队列有上限，满了丢弃最旧的一行。
   - 在 Task 3（LineQueue）和 Task 9（pty 写满、TCP 慢读者）中测试。
3. **画面里人脸过多**：输出行的长度必须有上限。`max_faces` 默认 10；按置信度保留前 N 个；`num` 表示实际输出的数量。在 Task 8 中测试。
4. **模型文件缺失或损坏**：`RetinaFace::load` 返回 false，m12d 以退出码 2 退出，并在 stderr 说明原因，不能带着空模型继续推理。在 Task 6 和 Task 12 中测试。
5. **温度文件读不到或格式异常**：连续 3 秒读不到有效温度，就按"过热"处理，暂停检测，直到恢复正常读数。在 Task 11 中测试。
6. **畸形输入**：包括半行、超长行、非 JSON、缺字段、类型错误、未知命令、CR/LF 混用。每种都要有确定的错误回复，不能崩溃，不能让一个错误的 cfg 只生效一半。在 Task 9 和 Task 10 中测试。
7. **TCP 客户端异常**：半行时断开、连接数超限、反复连接和断开。只关闭出问题的那个通道，串口不受影响。在 Task 9 中测试。

### Task 3：单槽最新帧缓冲与有界行队列（主机单元测试）

**Files：**
- 新建：
  - `src/core/latest_frame.{h,cpp}`、`src/core/line_queue.{h,cpp}`
  - `tests/test_main.cpp`、`tests/test_latest_frame.cpp`、`tests/test_line_queue.cpp`
- 修改：`CMakeLists.txt`
  - 加入 `m12core` 静态库。
  - `HOST=ON` 时加入 `m12tests`（doctest）并调用 `enable_testing()`/`add_test`。

**Interfaces：**
- Produces：
  ```cpp
  struct Frame { std::vector<uint8_t> yuyv; int w = 0, h = 0; uint64_t id = 0; int64_t ts_ms = 0; };
  class LatestFrame {
   public:
    void publish(Frame&& f);                       // 赋值 id = 上一个 id + 1，然后 notify_all
    bool wait_newer(uint64_t last_id, Frame& out, int timeout_ms); // 有更新的帧就拷贝并返回 true；超时或已 stop 返回 false
    void stop();                                   // 唤醒所有等待者，之后 wait_newer 立即返回 false
  };
  class LineQueue {
   public:
    explicit LineQueue(size_t capacity);
    void push(std::string line);                   // 队列满时丢弃最旧的一行，dropped()+1
    bool pop(std::string& out, int timeout_ms);    // 空则等待；超时或已 close 且为空时返回 false
    void close();
    uint64_t dropped() const;
  };
  ```

- [ ] **Step 1：写失败测试**
  - `test_latest_frame.cpp`：
    - `wait_newer returns published frame`：publish 一帧，`wait_newer(0,…)` 返回 true，并且 `out.id==1`。
    - `wait_newer times out when nothing newer`：已经 publish 一帧后，`wait_newer(1,out,50)` 返回 false，耗时 ≥45ms。
    - `stop wakes waiter`：另一个线程调用 `wait_newer(0,out,5000)`，主线程 10ms 后调用 `stop()`，等待线程在 200ms 内返回 false。
    - `skips to latest`：连续 publish 3 帧，`wait_newer(0)` 得到 `id==3`。
  - `test_line_queue.cpp`：
    - `drop oldest when full`：容量为 2，push "a" "b" "c"；pop 依次得到 "b" "c"，并且 `dropped()==1`。
    - `pop times out on empty`：`pop(out,30)` 返回 false。
    - `close unblocks pop`：另一个线程正在 `pop(out,5000)`，调用 `close()` 后它在 200ms 内返回 false。

- [ ] **Step 2：确认测试失败**
  - 运行：`scripts/env.sh sh -c 'cmake -S . -B build/host -G Ninja -DHOST=ON && ninja -C build/host m12tests'`
  - 期望：编译失败，报告找不到 `LatestFrame`/`LineQueue`。

- [ ] **Step 3：实现**
  - 用 `std::mutex` 加 `std::condition_variable`。
  - `wait_newer` 用 `wait_for` 配合谓词，禁止轮询。
  - 新建 `scripts/build.sh host|target`，把 cmake 加 ninja（host 时再加 `ctest --output-on-failure`）包装成一条命令。

- [ ] **Step 4：确认测试通过**

  - 期望：ctest 全部 PASS。

### Task 9：传输层：串口、TCP 与 IO 循环（用 pty 和本机回环测试）

**Interfaces：**
- Consumes：Task 3 的 `LineQueue`。
- Produces：
  ```cpp
  // 把字节流切成行；去掉行尾 \r；空行忽略。
  // 一行超过 max_len 时，丢弃到下一个 \n 为止，并以 too_long=true 回调一次。
  class LineSplitter { public:
    explicit LineSplitter(size_t max_len = 512);
    void feed(const char* p, size_t n, const std::function<void(std::string_view line, bool too_long)>& on_line);
  };
  int open_serial(const std::string& path, int baud);  // 原始 8N1，O_NONBLOCK|O_NOCTTY；失败返回 -1
  int open_tcp_listener(uint16_t port, int backlog);   // 0.0.0.0，SO_REUSEADDR，非阻塞；失败返回 -1
  using ChanId = int;
  struct IoStats { std::atomic<uint64_t> dropped{0}, rejected_clients{0}, clients{0}; };
  class IoLoop { public:
    // handler 在 IO 线程上执行；返回回复行（不含 \n），返回空串表示不回复
    using Handler = std::function<std::string(ChanId, std::string_view line, bool too_long)>;
    IoLoop(int serial_fd /* -1 表示无串口 */, int listen_fd /* -1 表示无 TCP */, size_t max_clients, Handler h);
    void run(std::atomic<bool>& stop);       // poll 循环
    void push(std::string line);             // 任意线程可调用：发给所有订阅了的通道，并用 eventfd 唤醒 IO 线程
    void set_subscribed(ChanId c, bool on);  // 只能在 handler 内调用
    bool subscribed(ChanId c) const;
    const IoStats& stats() const;
  };
  ```
- 行为约定：
  - 每个通道有自己的发送缓冲，上限 8KB。写入不阻塞；缓冲放不下整行时就丢弃这一行（绝不发半行），`dropped+1`。
  - `push` 的行先进入 `LineQueue(64)`，由 IO 线程取出后分发。
  - 连接数超过 `max_clients` 时：先接受，立即发送 `{"id":-1,"ok":false,"err":"busy"}`，然后关闭，`rejected_clients+1`。
  - 新的 TCP 客户端默认订阅推送，串口也默认订阅。
  - 某个客户端断开或出错时，只关闭这一个通道。

    - `strips CR`：`"x\r\n"` 得到 "x"。
    - `too long discarded once`：`max_len=8`，feed 20 个 `a`、一个 `\n`，再 feed `"ok\n"`。期望先收到一次 too_long 回调，然后收到 "ok"。
    - `empty lines ignored`：`"\n\n"` 不产生任何回调。

    - `serial reply stays on serial`：从 pty 主端写入 `"a\n"`，读到 `"R:a\n"`；同时连着的 TCP 客户端 200ms 内收不到任何数据。
    - `tcp reply stays on tcp`：与上一条对称。
    - `push to all subscribed`：`push("P")` 后两边都收到 `"P\n"`。在 handler 里对 TCP 通道调用 `set_subscribed(false)` 后再 push，只有串口收到。
    - `third client rejected`：`max_clients=2`，第 3 个连接收到 busy 行后被关闭，前两个连接不受影响。
    - `slow tcp reader does not block`：TCP 客户端始终不读。循环 push 5000 次，每行 200 字节。期望：总耗时不超过 2 秒，`dropped>0`；串口端一直在读，收到的每一行都完整。
    - `disconnect mid-line`：客户端发送 `"abc"`（没有 \n）后断开。期望 loop 不崩溃，handler 没有被调用。
    - `open_serial fails on missing path`：`open_serial("/nonexistent",115200)` 返回 -1。
    - `stop exits`：设置 stop 后，`run` 在 300ms 内返回。

- [ ] **Step 2：确认失败，实现，再确认通过**
  - 串口用 termios：`cfmakeraw`，加上 `cfsetispeed` 和 `cfsetospeed(B115200)`。
  - poll 集合包括：串口 fd、监听 fd、各个客户端 fd、一个 eventfd（push 时唤醒）。
  - 只有发送缓冲非空时才关注 POLLOUT。poll 超时设为 200ms，只用来检查 stop，不做轮询工作。
