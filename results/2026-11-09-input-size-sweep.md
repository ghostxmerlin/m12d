# 检测输入尺寸实验（1 米以内优先，2026-11-09）

## 方法

- 用 28 帧固定图片集，先经 m12d 的路径转成 320×240 RGB，再用 ncnn 的 bilinear 缩放到各个尺寸，然后用 mnet.25 检测。
- 工具：`build/host/scale_sweep`，由 `tools/scale_sweep.cpp` 编译。
- 每格的含义：检出数 / 最高 prob / 脸宽。脸宽按 640×480 坐标换算，单位 px。

## 设备推理耗时

`m12bench`，完整 9 个输出，2 线程，不采集。

| 输入 | 推理耗时 | 帧率上限 |
|---|---|---|
| 320×240 | 118.7 ms | 8.4 |
| 256×192 | 71.7 ms | 14 |
| 224×168 | 58.2 ms | 17 |
| 192×144 | 40.1 ms | 25 |
| 160×120 | 30.9 ms | 32 |

## 检出情况

| 场景（帧数，脸宽） | 320×240 | 256×192 | 224×168 | 192×144 | 160×120 |
|---|---|---|---|---|---|
| near 近距离（4 帧，约 100px） | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 |
| backlit 逆光（4 帧，约 95px） | 4/4 | 4/4 | 4/4 | 3/4 | 1/4 |
| far（4 帧，约 51px） | 4/4 | 2/4 | 4/4 | 4/4 | 0/4 |
| multi 两人中前面那位（4 帧，约 53px） | 4/4 | 0/4 | 0/4 | 4/4 | 0/4 |
| side 侧脸（4 帧，约 55–61px） | 4/4 | 3/4 | 1/4 | 3/4 | 1/4 |
| empty / multi2（8 帧，应为 0） | 0 误检 | 0 | 0 | 0 | 0 |

## 观察

- **检出率不随尺寸单调变化。** 256 和 224 反而比 192 差。原因是 stride 8 层的 anchor 是 16 和 32 px：
  - 约 52px 的脸，在 192 输入里约 16px，正好对上 16px 的 anchor；
  - 在 256 输入里约 21px，落在两个 anchor 之间，置信度就低。
- **192×144**：约 100px 的近脸全部检出；50–60px 的脸 11/12 检出；逆光漏 1 帧。
- **160×120**：只有近脸可靠。

## 距离粗估（未标定）

- 假设水平视场角约 65°、脸宽约 15cm，那么 100px 约 0.75m，50px 约 1.5m。
- 原来记录为"2m"的 far 场景，按这个估算更接近 1.5m。
- 只有一个人、28 帧，样本很小。

## 结论（供决策）

1 米以内的场景用 192×144：推理从 118ms 降到 40ms，约快 3 倍。在约 1.5m 的距离上，样本里大部分仍能检出。
