# 阶段 2：按需人脸识别 结果（2026-11-10）

- 设计：`docs/superpowers/specs/2026-11-10-m12d-phase2-face-id-design.md`
- 计划：`docs/superpowers/plans/2026-11-10-m12d-phase2-face-id.md`
- 分支：`phase-2`
- 设备条件：Wi-Fi 关闭，1.4 GHz，USB 供电，裸机

## 已实现

- 新增指令 `learn` / `who` / `forget` / `faces`，串口和 TCP 用同一套。回复是延迟的：请求先进队列，由检测线程在帧间处理，再经 `IoLoop::reply` 发回请求来源的通道。
- 调度：
  - 每帧最多做一次 MobileFaceNet 推理，`who` 优先于 `learn`。
  - 最多 4 个请求同时在处理，超出时回复 `busy`。每个请求从入队起计时，期限 3 s。
  - 待机时 learn / who 回复 `standby`，过热暂停时回复 `hot`。
- 识别结果写回检测行：认出的脸会在 `id` 之后带上 `"name"`，直到这张脸离开画面超过 1 s、和别的脸重叠、再次识别得到不同结果，或者这个名字被删除。
- 人脸库 `data/faces.bin`：
  - 带 CRC 校验；先写临时文件并 fsync，再改名，再对目录 fsync，掉电不会写坏。
  - 文件损坏时，坏文件被改名保留，以空库启动。
  - 每个名字最多 20 个样本，库里最多 16 个名字。新学的脸和库里别的名字太像时回复 `conflict`，不存。
- helloworld 页面有人脸识别面板：学习、识别、列出、两步删除。脸框上显示名字。

## 数字

| 项目 | 结果 |
|---|---|
| A 层：与原厂识别流程一致性（32 帧，同一输入） | 最小余弦 0.999999 |
| MobileFaceNet 单次推理（设备，2 线程） | 218 ms |
| `who` 往返（TCP，30 次，用户在画面中） | p50 265 ms，p95 445 ms |
| 主机单元测试 | 全部通过；B 层人脸检测一致性 56/56 不变 |
| 指令脚本（TCP） | 16/16 |

- 与原厂流程对齐，前后做了两步：
  - 一开始用 ncnn 的仿射变换函数做对齐，与原厂流程的最小余弦只有 0.996。改为逐字移植原厂的 `getAffineMatrix` / `warpAffineMatrix` / `resize` 之后，达到 0.999999。
  - 原厂在变换之后做一次 `bgr2rgb`，所以模型的实际输入是 RGB。
- 识别处理挪到了每次循环的开头，用上一帧检测到的人脸来算。这样请求不用再等本帧的人脸检测，p50 从 365 ms 降到 265 ms。
- p95 偏高，是因为识别有时和人形检测或 320 复核落在同一帧。

## 未达到的设计目标（模型速度决定）

- 设计要求延迟 ≤ 300 ms。MobileFaceNet 单次就要 218 ms，再加上等一帧，p95 达不到。
- 设计要求每秒一次 `who` 时，检测帧率下降不超过 10%。每次识别占用约 218 ms，相当于每秒约 22% 的计算时间，所以不可能做到。
- StackChan 平时只在需要时偶尔问一次（例如新面孔出现时），实际影响很小。以后要提速，可以试 int8 量化，或者换更小的模型。

## 准确性

**离线**：学习样本取用户的正脸 4 帧，加上阶段 1 近距离 1 帧。各场景下的最低相似度：

| 场景 | 最低相似度 |
|---|---|
| 侧脸约 45° | 0.47 |
| 约 2 m | 0.54 |
| 2.5 m 坐着 | 0.60 |
| 逆光 | 0.60 |
| 右转 30° | 0.68 |
| 其他姿态、暗光、笑 | ≥ 0.75 |

**用户现场检查**：在页面上学习一次（5 个样本），之后"这是谁"认出了用户，相似度 0.51–0.77，用时约 260–280 ms。用户的评价是"效果很好"。

## 局限，以及还没做的事

- **还没有"非本人"样本**。早上那张多人照片里检出的唯一一张脸是用户本人，另一个人被遮挡，没有检出。
  - 因此阈值仍是原厂的 0.5，不能保证不会把别人认成用户。
  - 等用户安排其他人按 `scripts/shots/others.txt` 拍照后，用 `scripts/faceid_eval.py` 定阈值。改阈值只需改 `RuntimeCfg::id_th` 的默认值，运行时也可以用 `cfg id_th` 调整。
- 设备验收里还没做两项：
  - 连续 60 s、每秒一次 `who` 时的帧率统计；
  - 拔电测试人脸库是否完好。
- 开机自动启动 m12d 放在阶段 5。
